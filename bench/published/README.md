# `bench/published/` — what a reader can check a number against

Generated by `bench/publish.py`; **do not hand-edit**. Every file here is the
machine output behind a number quoted in `PROTOCOL.md` §12 or `FINDINGS.md`.

This directory exists because the first round of this investigation published a
table of results and committed nothing that produced them. `results/` is
gitignored — one run is up to 23 MB and a full tier-1 pass is 654 MB — so
"reproducible" meant "re-run everything on a GPU for a day", and `PROTOCOL.md`
§5.6's rule that a corpus is frozen when its output is committed pointed at no
committed output.

## What is here

| pattern | what it is |
|---|---|
| `<label>__<corpus>.summary.json` | `score.py`'s aggregate for one run: nDCG@10, MRR, recall@k, and the same numbers per stratum, per gold-set size and per leakage class |
| `<system>-vs-<baseline>__<corpus>.stats.json` | `stats.py`'s paired comparison: mean Δ, BCa 95% interval, randomization p, per stratum, with the seed and the resample counts |
| `qrels.manifest.json` | one entry per query set: sha256, byte size, instance count, gold-file count, stratum sizes |

## How to use it

**To check a published number**, open the summary named by the arm and read
`ndcg@10`. Every figure in §12's tables is one of these.

**To check a published Δ**, open the stats file. It carries the interval and the
p-value together, which is the pair §5.2 requires — a p-value on its own says the
sign is probably right and nothing about whether the size is worth its cost.

**To check that your rebuilt corpus is the one these numbers came from**, run
`build_docs_qrels.py` (or `build_ident_qrels.py`) and compare the sha256 of the
file it writes against `qrels.manifest.json`. The qrels themselves are not
committed: they are derived from third-party datasets pinned by commit in
`corpora.toml`, and a hash is what lets both sides confirm they hold the same
set without either shipping it. A mismatch means the upstream dataset, the
resolver or a `corpora.toml` revision moved — all three are things a reader
should be able to detect.

## What is deliberately not here

The **per-query rows**. They are the bulk of a run, they are regenerable, and
anyone who wants to re-derive a Δ from raw rankings should re-run the arm rather
than trust an archived one. `run.py --per-query` writes them locally.

The **corpora and the clones**. `corpora.toml` pins every dataset by HF commit
and every repository by `docs_commit`/`base_commit`; `fetch.py` and
`build_*_qrels.py` rebuild them, and `build_docs_qrels.py` hard-fails if a clone's
HEAD is not the pinned commit.

## Keeping it honest

`bench/publish.py --check` regenerates into a temporary directory and diffs. It
fails on three things, each of which is a real defect:

- **STALE** — a committed artefact no longer matches what its run produces.
- **UNCOMMITTED** — a cited run has no committed artefact.
- **ORPHAN** — a committed artefact that nothing in `publish.py`'s citation
  lists produces, i.e. a number that was withdrawn without its evidence.
